Design as code

Keep designs in a repository, and check them in review.

Write a design with a small JavaScript builder or as plain .ledesign.json, build pictures headlessly, review changes as a short list of layers, and let a pull request fail when a design overflows or leaves the brand. It all reads and writes the same open design format, so a built design opens in the studio as an ordinary one.

What it does

  • A builder of about 150 lines with no dependencies, for pages, text, images, shapes, icons and effects
  • Build, check and diff commands; diff can also write a picture of what changed
  • Check exits with an error when a design has problems, and takes an optional brand file
  • A GitHub Action in the agent kit runs the checks on a pull request
  • A built design is plain data: nothing in it runs when the studio opens it

How it works

  1. Install Node 20 or later and a Chromium-based browser, and set up the command line.
  2. Write poster.design.js with the builder, or a .ledesign.json by hand, and run the build command.
  3. Run check (with --brand if you have a brand file) and diff on old and new files, and add the Action to your pull requests.

Your files stay on this device

Everything runs on your own machine in a headless browser that cannot reach the network. Nothing is sent to LocalEditor.

Questions

Short, honest answers.

More on the privacy and install page.

Is the builder a second format?

No. It writes the same open design format the studio reads and writes. It is a convenience for people, agents and CI.

What does check look for?

Overflowing or clipped text, low contrast, missing images and unknown fonts. With a brand file it also reports colours and fonts that are not the brand's, and logos that are too small or crowded.

What do I need installed?

Node 20 or later and Chrome, Edge or Chromium. No other dependency.
