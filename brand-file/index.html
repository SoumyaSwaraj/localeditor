Brand file

Keep your brand in one plain file.

A brand file holds one brand as plain JSON: colours with roles, fonts by role, logos, spacing, tone words, and do and don't lines. You keep it in the Brand kit in the studio. An assistant or a script reads the same file and checks designs against it. It is data only, and nothing in it is ever run.

What it does

  • Colours with roles such as primary, accent, background and text, and fonts by role
  • Logos with the background they suit, clear space and a smallest width
  • Checks for colours and fonts that are not the brand's, text that is hard to read on a brand colour, and logos that are too small or crowded
  • Checks run from the command line, the MCP server and CI, and in the studio for a design that carries its brand inside it

How it works

  1. Write a brand.lebrand.json by hand or have an agent write it, or build the brand in the Brand kit.
  2. Import the file into the Brand kit, or keep it in your design folder.
  3. Name it in a design with the brand field, or pass it to the check command with --brand.

Your files stay on this device

The file is plain data on your own device. The reader refuses markup, web addresses and paths that leave the folder. Checks run where you run them, and nothing is sent to LocalEditor.

Questions

Short, honest answers.

More on the privacy and install page.

What is in a brand file?

A name, colours with roles, fonts by role, logos, spacing, tone words, do and don't lines, and two rules: whether pure black and white are allowed beside the palette, and the contrast ratio text must reach.

Does the studio check my design against it?

The studio checks a design that carries its brand inline. A design that names the file by path is checked by the command line, the MCP server and CI, because a browser cannot read a file by path.

How big can it be?

Up to 2 MB, with at most 40 colours and 8 logos. Embedded logos are PNG, JPG, WebP or GIF up to 256 KB each. SVG logos are not accepted.
